在 Linux Shell 中，反斜杠 `\` 可以用于转义后面的字符，因此可以将一个被黑名单过滤的关键字拆开书写。例如 `cat` 被过滤时，可以写成 `c\at`。对于简单的正则黑名单来说，输入字符串中并不存在连续的 `cat`，因此可能绕过检测；但当 Shell 真正解析命令时，反斜杠会被处理，最终执行效果仍相当于 `cat`。这种方法通常称为**反斜杠转义绕过**或**关键字拆分绕过**。

这种绕过产生的根本原因是**过滤器与 Shell 的解析规则不同**。程序通常只对用户输入的原始字符串进行关键字匹配，而 `system()` 等函数随后会把字符串交给 Shell 再次解析。攻击者可以利用 Shell 的转义、变量展开等机制，使过滤阶段看到的内容和最终执行的命令不同。例如 `fl\ag` 在过滤时可能避开对 `flag` 的匹配，但 Shell 解析后仍会得到 `flag`。因此，在安全设计中不应依赖简单的关键字黑名单来防止命令注入。
