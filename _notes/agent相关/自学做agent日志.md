# 确定agent的PEAS模型

## 漏洞挖掘智能体的 PEAS 模型

漏洞挖掘智能体（Vulnerability Discovery Agent）是一种基于人工智能的自动化安全检测系统，能够通过资产收集、指纹识别、漏洞检测、结果分析和漏洞验证等方式，自动发现目标系统中潜在的安全漏洞，并生成相应的漏洞报告。

使用 PEAS 模型，可以从性能度量（Performance Measure）、环境（Environment）、执行器（Actuators）和传感器（Sensors）四个方面描述该智能体的任务环境。

### 一、PEAS 模型描述

|PEAS 要素|具体描述|
|---|---|
|P：性能度量（Performance Measure）|① 漏洞发现数量及有效漏洞比例；② 漏洞检测准确率和误报率；③ 漏洞类型与资产检测覆盖率；④ 漏洞严重程度及风险评估准确性；⑤ 漏洞挖掘效率和资源消耗；⑥ 漏洞报告的完整性与可复现性；⑦ 检测过程的安全性和授权合规性。|
|E：环境（Environment）|① 获得授权的 Web 网站、服务器、API 接口及网络服务；② 目标系统的操作系统、Web 框架、数据库和中间件；③ 网络环境，包括防火墙、WAF、代理及网络延迟；④ 目标应用的业务逻辑、身份认证和访问控制机制；⑤ 漏洞知识库、CVE 数据库以及历史扫描记录；⑥ SRC 平台的授权范围和测试规则。|
|A：执行器（Actuators）|① 调用 Nmap、Nuclei、httpx 等工具进行资产识别与安全检测；② 在授权范围内发送 HTTP/HTTPS 请求，进行参数测试和接口分析；③ 根据检测结果动态调整扫描策略和测试顺序；④ 执行受控的漏洞验证操作；⑤ 将漏洞信息、请求响应和验证证据保存至数据库；⑥ 自动生成漏洞报告及修复建议；⑦ 对高风险测试请求人工审批。|
|S：传感器（Sensors）|① 获取 HTTP 请求与响应信息，如状态码、响应头、响应体；② 收集端口扫描结果、服务版本和技术栈指纹；③ 读取漏洞扫描工具输出及错误日志；④ 分析网页源码、JavaScript 文件、API 接口及参数；⑤ 获取漏洞知识库和历史检测数据；⑥ 接收用户输入的目标、授权范围、测试规则及人工反馈。|

### 二、漏洞挖掘智能体的任务环境特性

|环境特性|类型|原因分析|
|---|---|---|
|可观察性|部分可观察|智能体通常只能获取 HTTP 响应、开放端口和服务指纹等外部信息，无法直接了解目标系统内部代码、数据库结构及真实运行状态。|
|确定性|随机性|相同的检测请求可能受到网络延迟、服务器负载、动态令牌和 WAF 等因素影响，产生不同的结果。|
|动态性|动态环境|目标网站的服务状态、业务数据、安全策略和网络环境可能随时变化，智能体需要动态调整检测策略。|
|决策关系|序贯性|前一次检测结果会影响下一步行动。例如，识别出某种 Web 框架后，智能体可以进一步检查对应版本的已知漏洞。|
|状态表示|离散与连续混合|漏洞类别、HTTP 状态码、工具选择等属于离散数据，而响应时间、请求速率、风险评分等可以是连续数值。|
|智能体数量|单智能体或多智能体|基础系统可以由一个 Agent 完成全部任务；复杂系统可以由资产分析 Agent、漏洞检测 Agent、漏洞验证 Agent 等协同完成。|
|环境知识|部分未知|智能体通常无法预先掌握目标系统的完整架构和安全状态，需要通过持续观察、分析与测试逐步了解环境。|

### 三、智能体工作流程

1. 环境感知（Sensors）

获取授权资产、HTTP 响应、服务指纹和扫描结果

2. 智能分析与决策（LLM / ReAct）

识别潜在漏洞、分析风险并选择检测策略

3. 执行检测（Actuators）

调用安全检测工具，执行授权范围内的测试

4. 结果观察与漏洞验证

分析响应差异、识别误报、保存漏洞证据

5. 性能评估（Performance）

评估漏洞有效性、覆盖率、效率与报告质量

利用反馈结果优化下一轮检测策略
